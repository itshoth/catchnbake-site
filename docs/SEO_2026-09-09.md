## Cloudflare redirect correction

The old `_redirects` file used a full hostname as the source. Cloudflare Pages does not support domain redirects in that file. On September 9, the live www red grouper URL returned HTTP 200 instead of a redirect.

Create a Single Redirect in the catchnbake.com Cloudflare zone:

1. Name: `www to apex`.
2. Custom filter expression: `(http.host eq "www.catchnbake.com")`.
3. Dynamic target expression: `concat("https://catchnbake.com", http.request.uri.path)`.
4. Status code: `301`.
5. Enable Preserve query string.

Keep the rule scoped to www. Do not redirect the apex hostname to itself. Test the homepage, `/fish/red-grouper`, and a URL with a query string. Each www request should return a 301 to the same path and query on the apex, followed by a 200 for valid pages.

This setting is separate from the code change and has not been applied by editing `_redirects`.

Sources: [Cloudflare redirect support](https://developers.cloudflare.com/pages/configuration/redirects/) and [www to apex setup](https://developers.cloudflare.com/pages/how-to/www-redirect/).

## Content maintenance

New articles live in `scripts/new-species.js`. Editorial updates to existing guides live in `scripts/refresh-species.js`. The shared template lives in `scripts/build-species.js`. The builder also generates the guide directory, about page, navigation links, and sitemap.

Before publishing new articles, set their publication dates to the actual publication day. Update modified dates when the corresponding content changes. Do not advance dates just to suggest freshness.

The halibut article covers Pacific halibut, with Canadian links for Port Renfrew. Area 20 and offshore Area 121 may both matter depending on the actual fishing location. The guide directs readers to DFO rather than publishing limits that could go stale.

New articles currently omit species imagery. Add the owner's verified photos before the final editorial pass. Supply `images/fish/halibut.webp` and `.jpg`, and the corresponding red snapper files when available, at 1400 by 875. Set `hero` to true and provide a literal `heroAlt` description. Add actual article share images at 1200 by 630 and set `ogImage` to the matching root path. Remove location metadata before committing image files. Review the image before labeling a fish species.

Without an article photo, the page uses the existing brand share image and omits the Article image property. This avoids falsely labeling a different species. A suitable article photo remains part of the final publication work.

The guide template uses Article and BreadcrumbList structured data. It keeps visible questions and answers. It does not promise FAQ search enhancements, recipe rich results, or ratings that the content cannot substantiate. [Google article guidance](https://developers.google.com/search/docs/appearance/structured-data/article).

## Measurement and release

App Store badges send an `app_store_click` event to the existing Clarity integration, with the page stored as `app_store_click_page`. This measures the click, not an App Store installation. Confirm the event in Clarity after deployment.

Use a preview deployment to review the new guides and photos before merging to the production branch. After production deployment, test the redirect, page status codes, canonical tags, sitemap, mobile menu, and App Store badges. Submit the sitemap in Search Console and inspect the new article URLs. Save the deployment date so the next 28 day comparison has a clear boundary.

For a rollback, restore the previous Cloudflare Pages deployment. Manage the Cloudflare redirect rule separately.
